# 第三堂課 — 工作習慣 = 知識外部化 ⭐

> 課程總覽見 [00-overview.md](00-overview.md)。
> **通用能力**：專案管理 / 文件方法論（帶得走，任何 technical 工作都用得到）。
> ⭐ 這套是要傳承的 lab 工作方法論。
> **開場鉤子**（接第二堂 session 痛點）：「還記得每次都要跟它重講你的研究是什麼嗎？今天教你一勞永逸。」
> **核心訊息**：**Claude 會忘，但檔案不會。把記憶寫進檔案，Claude 每次自動讀。**
>
> **主線 vs 副產品（教學設計原則）**：
> - **主線 = 解決「Claude 會忘」**（剛需、好懂、接第二堂親身踩過的痛 → 動機最強）。整堂課明面上講這個。
> - **副產品 = 整理自己的知識資產**（為了讓 Claude 記住而寫 CLAUDE.md，其實就是在整理自己腦中散落的知識）。這層不當大旗扛、不一開始就講抽象價值 —— 讓它在學員動手寫的過程中**自然浮現**，收尾再點破。

---

## 三個檔 = 三種記憶（教學主軸）

> 用「Claude 的三種記憶」當框架，比「三個檔案」好懂。

| 檔案 | 哪種記憶 | 回答 | 類比 |
|------|---------|------|------|
| **CLAUDE.md** | 長期背景記憶 | 「這專案是什麼？」 | 給新同事的**專案說明書**（放桌上每天看）|
| **PROGRESS.md** | 歷史記憶 | 「我做過什麼？」 | **實驗紀錄本 / 病程紀錄** |
| **TODO.md** | 待辦記憶 | 「還要做什麼？」 | **待辦白板** |

---

## 3-1 為什麼需要

- 重演「關掉就忘」→ 痛點具體化 → 解法：記憶外部化到檔案。

## 3-2 CLAUDE.md（專案說明書）

- 放專案根目錄、Claude 進資料夾自動讀。
- 放什麼：研究主題 / 資料在哪 / 用什麼工具 / 特殊規則（例：你的 cohort 定義、特殊的分組建模邏輯）。
- **關鍵 demo = 有 vs 沒有 CLAUDE.md 問同一題，看回答品質落差**（比講十句都有說服力）。
- → 現場各填一份自己專案的 CLAUDE.md。

**起手式範本**（複製到專案根目錄 `CLAUDE.md`，把方括號換成自己的）：

```markdown
# [專案名稱，例：燒傷感染預後分析]

## 這是什麼
[一兩句：研究問題 + 設計，例：回顧性 cohort，預測燒傷住院病人發生感染的風險因子]

## 資料在哪
- 主資料：`./data/[cohort].csv`（去識別，以 ID code 識別）
- 資料字典：`./data/codebook.md`

## Cohort 定義
- 納入：[例：2015–2024 急性燒傷住院、TBSA ≥ 10%]
- 排除：[例：入院 24hr 內死亡、資料缺漏關鍵欄位]

## 工具 / 慣例
- Python（pandas / scikit-learn / statsmodels）
- 不平衡 outcome 報 AUROC / AUPRC，不只看 accuracy
- patient-level 切分，避免 leakage

## 特殊規則 / 踩過的坑
- [例：L/R 側分開建模，不可合併]
- [例：感染定義以 [某標準] 為準]
```

> 規則：**只放穩定的事實與規則**，待辦放 TODO、歷史放 PROGRESS（見下）。

## 3-3 PROGRESS.md（紀錄本）

- 每段做完叫 Claude「把今天做的記進 PROGRESS」。
- 用途 = 跨 session 記憶 + 寫 paper 回溯「我當初怎麼處理的」。
- 對研究者：annual report / 論文進度靠這個。

**範本**（倒序，最新在上）：

```markdown
# PROGRESS — [專案名稱]

## 2026-06-21
- 完成 cohort 清理：原始 1,799 筆 → 排除後 1,778 筆（排除原因見下）
- 跑了缺值分析：`tbsa` 缺 3.2%、`infection_flag` 無缺
- 決策：年齡用中位數補值（分布右偏，不用平均）
- 下一步見 TODO

## 2026-06-18
- 拿到去識別 cohort，確認欄位與 codebook 一致
```

- 收尾固定動作：跟 Claude 說「**把今天做的記進 PROGRESS.md**」，它會自動 append。

## 3-4 TODO.md（待辦白板）

- P0（必做）/ P1（次要）分級。
- 跟指導者協作：他看你的 TODO 就知道卡在哪（呼應 lab 定期 progress report）。
- **只放待辦**：做完的移去 PROGRESS、作廢的直接刪，別讓它越積越長。

**範本**：

```markdown
# TODO — [專案名稱]

## P0（這週必做）
- [ ] 補完 Table 1（baseline characteristics）
- [ ] 確認感染 outcome 的時間窗定義（問指導者）

## P1（之後）
- [ ] 跑 logistic regression + 算 OR / 95% CI
- [ ] 畫 forest plot
```

## 3-5 把習慣串起來

- 一個專案完整節奏 = CLAUDE.md 建好 → 做事 → 收尾叫它更新 PROGRESS / TODO → 下次無縫接上。

## 3-6 收尾點破 — 一個你會慢慢發現的好處（副產品）

> 主線講完了（解決 Claude 會忘）。最後一分鐘點破那層更深的價值，讓它落地當 bonus，不當負擔。

- 你為了讓 Claude 記住而寫這些檔，其實是在**整理自己的知識**：
  - 把腦中散落的（cohort 怎麼定義、為什麼這樣排除、之前踩過什麼坑、看過哪些文獻）→ 變成**寫下來、可回溯、換人也接得住**的知識資產。
- 三個檔的另一個身分：
  - **CLAUDE.md** = 你這專案的「知識總綱」（定義 / 決策 / 規則）
  - **PROGRESS.md** = 你的「研究歷程沉澱」（做過什麼、為什麼這樣做 → 寫 paper 時的金礦）
  - **TODO.md** = 你的「下一步思緒」
- 一句話：**寫的當下是整理自己，寫完 Claude 剛好能用 —— 一魚兩吃。** AI 讀得到只是 bonus，真正受益的是未來的你。
