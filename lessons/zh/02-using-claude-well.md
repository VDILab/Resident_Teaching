# 第二堂課 — 怎麼用 Claude Code 用得好（技巧 / 心法）

> 課程總覽見 [00-overview.md](00-overview.md)。
> **通用能力**：跟 AI 協作的基本功（怎麼問、怎麼控制它、怎麼自救）。
> **開場鉤子**（接第一堂）：「你已經會跑了。但同一個 Claude，有人用得很順、有人一直撞牆——差別不在工具，在**怎麼用**。今天教的就是這個。」
> **定位**：第一堂是「會開機」，這堂是「**會開機之後，怎麼用得好**」。全是日常天天用得到的小技巧，不是高階功能。

---

## 2-1 怎麼問才有用（prompt 基本功）

> 工具再強，問得爛也得不到好答案。這節是投報率最高的一節。

- **爛問法 vs 好問法**（臨床研究情境對比）：

  ❌ 爛問法（太模糊，它只能亂猜）：
  > 幫我分析資料

  ✅ 好問法（給檔名、給要什麼、給格式）：
  > 讀這資料夾的 `cohort.csv`，告訴我每欄的缺值數，以及年齡的中位數與 IQR。

  ❌ 爛問法：
  > 畫個圖

  ✅ 好問法：
  > 把 TBSA 對住院天數畫成散點圖，加上趨勢線，存成 `tbsa_los.png`。

- **三個心法**：
  1. **給 context**：你的研究在做什麼、這個檔是什麼、你想要什麼格式。講越清楚，答越準。
  2. **一次一件事**：別一句話塞五個要求，拆開來問，好追、好改。
  3. **要它先說計畫**：複雜任務先叫它「**先別動手，告訴我你打算怎麼做**」，你看過再放行（接 2-3）。

---

## 2-2 好用的 `/` 指令（slash commands）

> 在 Claude 對話裡打 `/` 開頭的指令，是內建快捷功能。零基礎只要記幾個最常用的。

- **`/clear`** = 清空當前對話、重新開始（不用關掉重開 iTerm2）。對話變亂、想換個任務時最好用。
- **`/login`** = 重新登入（權限怪怪的、或剛被加進團隊時用）。
- 打 `/` 就會跳出清單，不用背——看得懂的就用。

### 進階：把你常打的話，做成自己的 command 🛠️

> 上面是 Claude 內建的；你也可以**自己做**。這是進階一階，**之後熟了再用**——但很實用，先知道有這回事。

- **動機**：2-1 教過「好 prompt 要給清楚」，但有些話你**每次都要重打**（例：「做敘述統計 + 每欄缺值表 + 把年齡分布存成 png」）。把它存成一個 command，以後打 `/eda` 一個字就觸發，不用每次重打。
- **怎麼做**（只要建一個檔）：在專案資料夾裡建 `.claude/commands/<名字>.md`，把那段固定話寫進去。例如建 `.claude/commands/eda.md`：

  ```markdown
  讀這個資料夾的主 cohort CSV，幫我做：
  1. 有幾筆、幾個欄位
  2. 每欄缺值數與比例
  3. 連續變項的中位數 + IQR；類別變項的次數表
  4. 把年齡分布存成 age_dist.png
  ```

- **用**：下次在這專案打 `/eda` → Claude 就照這段跑，省去重打。
- **心法**：**任何你重打第三次的話，就值得做成 command。** 固定的分析流程、固定的問法、固定的格式要求，都可以。
- （你也可以叫 Claude 幫你做：「把剛剛那段需求存成一個叫 eda 的 slash command」，它會幫你建好檔。）

## 2-3 計畫模式 — 讓它「先說再做」（最該養成的安全習慣）

> 零基礎最怕「它擅自改了我的檔 / 跑了我看不懂的東西」。解法：讓它動手前先報計畫。

- 心法一句話：**複雜或會改檔的任務，先叫它報計畫。** 直接這樣打：

  > 先別動手。先告訴我你打算怎麼做、會改哪些檔，我確認後再開始。

- 你看過計畫 → 覺得對 → 回它：

  > 可以，照這樣做。

  → 覺得不對 → 當場糾正（「第 2 步不要，改成…」），省得它做錯一大圈。
- 為什麼重要：你隨時握有控制權，不會被它牽著走；也是你看懂「它到底要幹嘛」的機會。
- （進階：Claude Code 內建 **plan mode**，按 `Shift+Tab` 可切換成「只計畫、不動手」的模式——之後熟了再用，現在先靠上面這句話就夠。）

## 2-4 讓它讀檔 / 讀文獻當參考

> 醫師天天讀 paper——這招超有感。

- 你可以把 **PDF、文獻、範例檔、別人的程式碼**丟給它讀，當作回答的依據。
- 例：「讀這篇 `reference.pdf`，幫我整理它的 study design 跟 outcome 定義」/「照這個 `example.py` 的寫法，幫我改成讀我的資料」。

**三種叫它讀檔的方法（由精準到廣）：**

1. **用 `@` 直接點名檔案**（最精準、最推薦）—— 打 `@` 會跳出檔案清單，選你要的，它就只讀那個：

   > 幫我看 @reference.pdf 的 outcome 定義，跟 @my_protocol.md 對一下有沒有出入。

   `@` 的好處：不用打全路徑、不會讀錯檔、它也清楚知道你指哪個。

2. **講檔名讓它自己找** —— 不打 `@` 也行，直接說「讀這資料夾的 `cohort.csv`」，它會在當前資料夾找。

3. **讓它讀整個專案** —— 不確定資料在哪、或要它綜觀全局時，直接叫它掃整個資料夾：

   > 看一下這整個專案資料夾，告訴我有哪些資料檔、各是什麼、彼此關係。

   它會自己 `ls` 進去探索。適合剛接手一個專案、想讓它先「摸清楚」的時候。

- ⚠️ 守第一堂的 PHI 底線：讀**去識別**的檔 OK；別把含姓名 / 病歷號的原始病歷丟進去（讓它掃整個資料夾前，先確認夾裡沒有未去識別的原始檔）。

## 2-5 出錯了怎麼自救

> AI 答錯、報紅字錯誤都很正常。會自救 = 不用每次都等指導者。

- **看不懂的錯誤訊息**：直接整段複製貼回對話框問它「這是什麼意思、怎麼修」——它很會解讀自己的錯誤。
- **答錯 / 不是你要的**：別重開，直接追問「不對，我要的是 X，你剛剛 Y 了」——給它更多 context 修正。
- **真的卡死**（額度、登入、裝不起來）：查[官方文件](https://docs.claude.com/en/docs/claude-code/overview)，或問指導者。

## 2-6 session 是什麼（為什麼關掉就忘、為什麼要存檔）

> 只給「會影響怎麼用」的直覺，不講 token / context window 數字。

> 還記得第一堂速覽小卡提過的 **session** 嗎？這裡把細節講清楚。

- **一次 `claude` 開到關 = 一個 session**；session 裡 Claude 記得你前面講過的話（像一場連續對話）。
- **關掉就忘**：session 結束，Claude 不記得上次聊什麼（它沒有跨天記憶）→ 重要結論要自己存檔。
- **越聊越鈍 / 會「滿」**：一個 session 塞太多（讀一堆大檔、聊很久）會變慢或忘前面 → **新任務開新 session**（或 `/clear`）。
- 實用習慣（80/20）：一個研究任務 = 一個 session；重要產出讓它**寫成檔案存下來**（別只留對話裡）；對話變怪 → `/clear` 或開新 session。

---

## 2-7 把產出存成檔（別只留在對話裡）

> 對話會消失，檔案會留下。這是「用得好」最關鍵的一條。

- 養成習慣：分析結果、整理好的表、寫好的程式，都叫它**寫成檔**（`.md` / `.csv` / `.py` / `.png`）存進你的資料夾。
- 為什麼：① 對話關掉就沒了，檔案不會 ② 下次可以接著用 ③ 寫 paper 時回去翻得到。
- 🔗 **埋伏筆接第三堂**：「關掉就忘」這個痛，下一堂用 CLAUDE.md / PROGRESS.md / TODO.md **把記憶外部化到檔案**徹底解決，連「每次重講專案」都免了。

---

## 第二堂結束 — 學員帶走什麼

- 會把問題問清楚（給 context、一次一件事、要它先說計畫）。
- 會用 `/clear` 等基本 `/` 指令、會讓它讀檔當參考。
- 出錯會自救（貼錯誤回去問、追問修正）。
- 懂 session「關掉就忘 / 要存檔」，養成把產出寫成檔的習慣。

> 一句話：**從「會跑」到「用得順」。**
